TenangLife UI/UX Audit

A full review of the single-page sound healing site (Next.js 16.4.3): layout, alignment, spacing, typography, images, accessibility, motion, and an image and performance plan for Vercel that stays clear of the Image Optimization quota.

Audited 1 November 2026 on the local dev build (localhost). Tools: Vercel Labs agent-browser for screenshots and in-page measurement, and the Vercel Web Interface Guidelines as the rule set. Viewports: 1440×900, 1366×768, 1280×720, 1024×768, 768×1024, 390×844. Audit only: no project code or configuration was changed.

1. Fix these first

  1. Text shrinks with the window height. At 1024×768, 66 of 115 text elements are under 14px and the smallest is 10.4px. At 1280×720 the smallest is 12.6px. (C1)
  2. The "Book a session" button breaks onto two lines at 1280px wide and below, and the vine covers it at 1024px. (C2)
  3. All section text starts invisible (opacity 0) until JavaScript runs, so it is blank without JS and the hero heading paints late. (C4)
  4. Footer text is unreadable: contrast is 1.8:1 on desktop and 4.2:1 on mobile; 4.5:1 is the minimum. (C5)
  5. Two booking cards link to the wrong place. "For 2 in Ubud" opens the 1:1 online booking page. (C6)
  6. The hero photo is blurry: a low-resolution, motion-blurred image that is also zoomed to 118%. (H1)
  7. Headings collide with the text below them in Soundchronized and Workshop. (H5)
  8. Left edges don't line up inside sections, with offsets of up to 57px. (H6)
  9. Events and Workshop are congested, and the same bowl, leaf and flourish decorations repeat in every section. (H7, H8)
  10. Images: 3.85 MB of mostly oversized PNG and JPEG files. Pre-resize them to AVIF/WebP, then switch on images.unoptimized. (Section 9)

2. Your rules: compliance check

Pass No play or pause button

The Stories slideshow and the instrument ribbon have no play/pause control. Keep it that way.

Make it work without one: generic guidance (WCAG 2.2.2) normally asks for a pause control on motion that lasts more than 5 seconds. You can meet that intent without a button. Stories already pauses on mouse hover and keyboard focus (Testimonials.tsx:47-50). It still needs to (a) pause on touch or pointer-down, because phones never hover, (b) stop when off-screen, and (c) stop under reduced motion, which it already does. The ribbon already stops under reduced motion; it should also stop when off-screen.

Pass No numbers on the slideshow or moving images

The slideshow shows dots only, and the ribbon shows words only. Two screen-reader-only strings contain numbers ("Story 4 of 6", Testimonials.tsx:107 and :165). They are never visible. Keep them for blind users, or switch them to "Story from Petra" if you want no numbers anywhere.

The Workshop modules show "01 to 04" (Workshop.tsx:63). That isn't a slideshow, but each module already has an icon, so the numbers are redundant (see L1).

Fails Spacing no more than 5px

Read literally, a 5px cap on every gap would squeeze buttons, line height and card padding, and make the page more congested. So this audit applies the rule where it clearly helps: gaps between sections and empty dead bands must be 5px or less. Sections already touch (0px apart), but there are large empty bands inside them and visible seams between them. See the next section.

4. Critical issues

CriticalC1 Text size depends on window height, so it becomes unreadable on common laptops

On desktop every section is drawn on a fixed 1672×841 "design canvas" that scales by --u = min(width/1672, height/841) (globals.css:230, :327). Font sizes are multiples of --u, so a shorter or narrower window shrinks all text.

ViewportSmallest textElements <14pxElements <16px
1440×90014.6px0 / 11528
1366×768 (most common laptop)13.6px26 / 11541
1280×72012.6px28 / 11559
1024×768 (iPad landscape)10.4px66 / 11571

Fix: put a floor on the scale, e.g. --u: max(0.86px-equivalent, min(...)), and give body text max(16px, calc(22 * var(--u))) with small text at least 14px. Better long term: build desktop sections with grid/flex and clamp() type, and keep design-pixel positioning only for decoration.

CriticalC2 Header "Book a session" button wraps and gets covered

At 1280px and below, the main call-to-action breaks onto two lines ("Book a / session") because Header.tsx:133 has no whitespace-nowrap, and the 1fr auto 1fr grid with lg:pl-[10vw] lg:pr-[8.5vw] (Header.tsx:90) leaves too little room. At 1024px the hero vine (Hero.tsx:40-47, z-30) overlaps the button.

Fix: add whitespace-nowrap; below 1280px use smaller side padding, px-6 on the button and nav gap-1; keep the vine under the header (z-index) or start it below the header height.

CriticalC3 Fixed-height sections clip content when the user zooms text

Desktop sections are locked to height: var(--screen) with overflow: hidden (globals.css:305, :323), and the hero to 100svh (:227). If someone uses a larger default font or 200% text zoom (WCAG 1.4.4 / 1.4.10), the text can't grow, so it is cut off or overlaps. The same thing happens when copy gets longer, for example in the Bahasa version.

Fix: use min-height in place of height and let content define the height; keep only decorative layers absolutely positioned.

CriticalC4 Page text is invisible until JavaScript runs

Reveal.tsx:20 renders every heading, paragraph and card with opacity: 0 in the server HTML, and the hero motion.h1 does the same (Hero.tsx:65-67). Before hydration (slow phones, poor signal, JS errors, some crawlers and link previews) sections are blank, and the hero heading paints late, which pushes back LCP (the main-content load time).

Fix: keep the hero fully visible with no entrance animation on the LCP text. For other sections, use a CSS class added by an IntersectionObserver, with a <noscript> or .js guard, so content is visible by default.

CriticalC5 Footer text fails contrast

Desktop: cream #fdf1e0 on the light-teal wave (sampled rgb(136,192,193)) is 1.8:1 (Contact.tsx:88-111). Mobile: cream on bg-reef #287e8e is 4.2:1, which still fails for 14px text. The footer logo is the same cream colour and almost disappears.

Fix: put the footer on a solid band of --color-pine #0d4f5c (≈8.2:1 with cream), full width, below the waves.

CriticalC6 Booking cards point to the wrong pages

  • site.ts:74-77: the Sounditation card "IDR 1.400.000, For 2 in Ubud" links to /booking-calendar/sounditation-1-1-online, the 1:1 online booking. Visitors book the wrong product.
  • site.ts:79-83: the card's price slot says "Home service" with the label "Group for Retreat / Event", and it opens a Canva deck. It is the only card with no price and no booking, so it reads as a price card but behaves like a brochure link.

Fix: confirm the correct URLs with the business. Make "Home service" a separate text link ("Retreats & events → see deck"), not a price card.

5. Section by section

Header

MediumM8 Logo crowded by the daisy illustration

The 30%-opacity daisy (.hero-daisy, globals.css:192 and :262) sits behind and over the 84px logo, so the hand-drawn petals merge with the logo's own flower mark. Fix: move the daisy below the header line or drop it to 12% opacity.

LowM13 theme-color doesn't match the page

layout.tsx:21 sets #fdfcf9, but the header sits on #f5ebe1 (hero) and #fef6ef (scrolled). Use #fef6ef.

Hero

HighH1 The hero photo is soft and blurry

hero.jpg is 1463×787, motion-blurred, and enlarged a further 118% (Hero.tsx:163 scale-[1.18]) into a ~626px circle, which needs about 1250 device pixels on retina screens. It is the most important image on the page and the least sharp. The alt text mentions singing bowls that the crop removes.

Fix: use a sharp original of at least 1600px with a face or hands in focus, and remove the extra scale.

MediumM9 Vertical balance: empty top, crowded bottom

There are 171px of empty space above the heading (250px at 1024px), while the buttons sit on top of the blue waves and the still-life overlaps the photo ring. "Therapy" nearly touches the quote. Fix: centre the copy block vertically, add 24px between the heading and the quote, and keep the buttons above the wave crest.

MediumH13a Mobile hero: photo below the fold, uneven buttons

At 390px, both CTAs stack at different widths (246px vs 213px), and the photo only starts at ~600px, below the first screen. Fix: make both buttons full width, and show a smaller photo (or crop) next to or above the heading.

Intro ("Don't let stress…")

HighH14 Dead bands and a hard edge

See the spacing table. On desktop, the pale-aqua water ends in a hard horizontal line at the Sounditation boundary. The blurred, rotated leaves (Intro.tsx:28 blur-[3px]) look like an out-of-focus mistake rather than depth. Fix: remove the blur, shorten the ribbon box on mobile, and continue the water colour into the next section's top edge.

Sounditation

HighH6a Price cards misaligned and sitting on the wave

Heading at x=704, body at 705, chips at 702, cards at 647 (57px further left, Therapies.tsx:119 box x=751 vs heading x=818). At 1280×720 the cards overlap the photo's swoosh and the bottom teal wave. The "Group for Retreat / Event" label wraps to 2 lines, so the three cards' labels no longer line up. The chips wrap 2 + 1, leaving a ragged row.

Fix: align the cards to the heading x, shorten the label ("Retreats & events"), and allow 2 chips per row or a short single list.

Soundchronized Therapy

HighH5a Heading descenders hit the tagline

"Therapy" is set at line-height 0.8 (Therapies.tsx:69), and the "p" and "y" run into "Sync body, emotion and energy". The body text is only 7px above the chips. The cards (x=129) stick out past the heading (x=140) and text (x=145).

HighH3 Unflattering photo crop

object-[22%_85%] (site.ts:87) shows only a nose and mouth under a bright red eye mask, cut at the eyes. It reads as a medical close-up, not as calm. Fix: crop to show the bowl resting on the body, or choose another photo.

Soundpuncture

MediumH2a Low-resolution photo and an empty right half

soundpuncture.jpg is 507×503 and is displayed at ~560 CSS px (≈1120 device px on retina), so it looks soft. There is 52px between the body and the chips here but 7–18px in the sibling panels, which is inconsistent. The single price card leaves the whole lower-right empty while the bowl crowds the bottom corner. Fix: use a larger source and keep the same vertical rhythm as the other therapy panels.

Workshop

HighH5b · H7a Collisions and congestion in the left column

The "p" of "Workshop" touches "Healing", and the "py" of "Self-Therapy" touches "An in-depth…" (Workshop.tsx:34, line-height 0.86). The column packs a 3-line heading, body, four bordered cards, a price and a CTA into one screen. Left edges: heading 142, body 143, cards 119, price 156. The plumeria is half hidden behind the "Led by" badge (Workshop.tsx:100).

Fix: show the modules as a simple 2×2 list without card borders (icon + title + line), put the price and CTA on one line aligned to the heading, and drop the plumeria.

Event, Home Service & Retreat

HighH7b · H4 The most congested screen

Two photos, a bowl cut-out, leaves, a heading with a flourish, five benefit cards and three buttons all share one screen. The buttons are squeezed into the sixth grid cell (Events.tsx:97), so "WhatsApp" wraps onto its own row. The "Flow" card is taller than the others. The inset photo (og.jpg, Events.tsx:53-59) is a cluttered candid shot (stroller, garden chairs, rug piles) and covers the main photo's subject. Left edges: heading 711, cards 702.

Fix: remove the inset photo; use a 2-column benefit list of 6 items, or 5 items with a 3-up row; put the buttons on their own full-width row under the list; use one primary CTA.

Stories (testimonials slideshow)

HighH10 Slideshow behaviour (no play/pause and no numbers, as you asked)

  • It auto-advances every 8s (Testimonials.tsx:12). The longer quotes (200+ characters) take about 10–12s to read.
  • Pause only happens on hover or focus (:47-50). On phones it never pauses, and it keeps rotating while off-screen, so the quote changes as you scroll to it.
  • On mobile the name list is hidden (:72 hidden lg:block), so the only control is a row of 14×28px dots (:154), well under the 44px touch target. There is no swipe.
  • Card height changes with each quote on mobile (min-h-[20rem], :110), which pushes the page below it.
  • Font size changes per quote (:124), so the slides look inconsistent.
  • The closing quote mark floats in the middle of the card, next to the name (:137), not after the quote.
  • The long quote is set in the condensed display face; see H12.
  • The bowl cut-out covers the card's bottom-right corner (:143).

Fix, with no added buttons or numbers: pause on pointerdown/touch and when out of view (IntersectionObserver); use 11s, or 4s + 35ms per character; keep the dots but give them a 44×44px hit area; add swipe; reserve the height of the longest quote; use one font size; put the closing mark after the text; move the bowl off the card.

Contact and footer

MediumM2 Weak input focus and an uneven form rhythm

The outline is removed (ContactForm.tsx:108 focus:outline-none focus-visible:outline-none), so the only focus cue is the 1.5px bottom line changing from #93b6b9 to #0d4f5c. There is a large gap between the "Email" field and the "Your message" label. The ring decoration sticks out past the card on the right. Fix: make the underline 2px or thicker with a soft background tint on focus, and use even field spacing. The footer contrast is covered in C5.

Every section repeats the same formula (leaves top-left, an oval photo with a gold ring, a bowl bottom corner, a flourish under the heading, teal waves). Typography

HighH11 Fake (browser-slanted) italics in display headings

Imbue only comes in an upright style (fonts.ts:5-10 loads no italic), so "peace.", "heard", "touch", "Retreat", "Workshop" and all four taglines use a browser-generated slant. At 40–130px it looks mechanically skewed. Fix: set the italic accents in Crimson Pro Italic, which is already loaded, or remove the italics.

HighH12 Long quotes set in a condensed display face

40-word testimonials in condensed Imbue (Testimonials.tsx:123) are tiring to read. Use Crimson Pro Italic at 20–24px for quotes.

MediumM10 Ragged rows

Chip rows wrap 2+1 (Sounditation, Soundchronized) and 3+wrap (Intro, mobile). The Events "Flow" card is taller than its neighbours. Shorter chip text or a fixed 2-column chip grid fixes this.

Mobile layout

HighH13 Inconsistent image order

At 390px the photo comes before the text for Sounditation, Soundpuncture and Events, but after it for Soundchronized and Workshop. Pick one order, image first, for every panel. The three stacked Sounditation price cards also take a full screen; a compact 3-row list would halve that.

7. Accessibility and interaction

MediumM1 Touch targets under 44px

Events buttons are 39–42px tall (Events.tsx:98-106 lg:min-h-0); story names are 33–43px; hero buttons are 35px at 1024px (calc(57*var(--u))); story dots are 14×28px at every size.

MediumM3 Price-card link names are confusing

The whole card is one link with a screen-reader-only "Book {label}" in the middle (Bits.tsx:49). A screen reader announces "IDR 1.400.000 Book For 2 in Ubud For 2 in Ubud 75 min", and the link opens a new tab without saying so. Fix: aria-label="Book Sounditation for 2 in Ubud, IDR 1,400,000 (opens in new tab)".

MediumM3b The tab pattern is incomplete

The story list uses role="tablist"/tab (Testimonials.tsx:72-79), but there is no arrow-key navigation, and the panel is role="group" rather than tabpanel. Either complete the pattern or use plain buttons with aria-pressed.

MediumM4 Constant background motion

The instrument ribbon runs a requestAnimationFrame loop that writes startOffset on every frame and never stops off-screen (FlowingText.tsx:43-50). There are 5 parallax useScroll hooks (Frame.tsx:38), and the vine sway and twinkle run forever. This drains battery on phones. Fix: pause the ribbon outside the viewport, and drop parallax on mobile.

9. Image and performance plan (Vercel-safe)

Current state: 25 image files, 3.85 MB in public/images. Today Next.js resizes them on the fly through Vercel Image Optimization, which uses the plan's quota. Switching that off without pre-resizing would send the full originals to every visitor (≈3.8 MB). So the plan does both: resize locally once, then turn off the service.

Implementation plan (for later; nothing applied during the audit)

  1. Keep originals out of the deployment. Move the masters from public/images to a source folder outside public/ (for example assets-src/, kept out of the deployed bundle), and commit only the optimised outputs. That keeps the Vercel upload small and avoids duplicate copies.
  2. Add one local script, scripts/optimize-images.mjs, using sharp (already installed as a Next.js dependency; add it to devDependencies explicitly). It writes:
    • Photos: AVIF (q≈55) + WebP (q≈72) at 640, 960 and 1400px widths.
    • Cut-outs (bowls, leaves, plumeria, vine, still-life, flower): AVIF + WebP with alpha at their native size, which is already 1× of the design.
    • Logos: 200px and 400px WebP + PNG fallback. Favicons: 32, 48 and 180px PNGs as app/icon.png / app/apple-icon.png.
    • OG image: a dedicated 1200×630 JPEG (~120 KB).
    • Delete flower-icon.png; keep grain.png.
  3. Turn off Vercel Image Optimization by merging this into the existing config. Keep every current setting: 
    // next.config.ts (planned change; not applied during the audit)
const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
  images: {
    unoptimized: true, // serve pre-built files as-is; no Vercel optimization quota
  },
  turbopack: { /* unchanged */ },
};
  4. Keep responsive delivery. With unoptimized, next/image no longer generates a srcset (bundled docs, image.md "unoptimized"). Add a small <Picture> component that outputs <picture> with AVIF and WebP <source srcset="…-640 640w, …-960 960w, …-1400 1400w" sizes="…"> and an <img> fallback. It always sets width/height (no layout shift), decoding="async", and loading="lazy" on everything below the fold.
  5. One high-priority image only: the hero photo gets fetchPriority="high" and loading="eager". Remove priority from the flower, vine and logo (it is deprecated in Next 16 in favour of preload).
  6. Correct sizes for each image: photos (min-width:1024px) 40vw, 90vw; hero (min-width:1024px) 45vw, 100vw; decorations get fixed widths matching their design size.
  7. Fonts: drop the unused TT Chocolates Light and Light Italic files. Three families (Imbue with its opsz axis, Crimson Pro normal+italic, TT Chocolates) is heavy for a one-pager; consider using Crimson Pro for both copy and accents.
  8. JavaScript: motion is loaded for simple fade-ins. A CSS + IntersectionObserver reveal removes most of that client JS and fixes C4 at the same time. Remove the dead CSS listed in section 8.
Expected result: the image folder drops from 3.85 MB to about 0.45–0.7 MB (≈80–88% smaller). The first screen downloads about 60–90 KB of images instead of about 650 KB. Vercel Image Optimization use drops to zero.

10. Suggested fix order

  1. Content and links: C6 (wrong booking URL), C2 (CTA wrap).
  2. Readability: C1 (text-size floor), C5 (footer contrast), H5 (descender collisions), H11 and H12 (italics, quote font).
  3. Layout: C3 (min-height instead of height), H6 (one left edge per column), the spacing table (dead bands, seams), H13 (mobile order).
  4. Images: replace or re-crop H1–H4, then run the optimisation plan (section 9) and switch on images.unoptimized.
  5. Decluttering: H7–H9 (remove the inset photo, cap bowls at 2, cut the flourishes).
  6. Interaction: H10 (slideshow pause on touch and off-screen, target sizes), C4 (visible-by-default reveal), M1–M4.
  7. Before you ship: re-run this audit at 1366×768, 1024×768 and 390×844, and run Lighthouse on the Vercel preview.
